# Вартість агентських рев’ю у Pull Requests

Дата — 2026-11-22

[План реалізації](../../tasks/plan.md) · [Задачі та перевірки](../../tasks/todo.md)

## 1. Контекст і цілі

Автор або рев’юер PR має бачити вартість останнього рев’ю у списку PR, а потім звіряти суми окремих запусків в історії та в деталях запуску. Вартість показуємо в USD після завершення. Ціна конкретного агента збігається в таймлайні й сайдбарі, а для одиночної команди вона також дорівнює сумі в списку PR.

Скриншоти користувача визначають розміщення поля. Значення на них ілюстративні. Скриншот сайдбара показує Security Reviewer. Та сама картка `Cost` потрібна для General Reviewer та інших агентів, які запускаються для PR.

## 2. Три екрани

| Екран | Розміщення | Вміст |
|---|---|---|
| **Pull Requests** · скриншот 3 | Окрема колонка `Cost` після `Status` і перед `Updated` у поточному списку | Вартість останньої завершеної команди рев’ю. Для `Run all` це сума вартостей агентів. Якщо відома лише частина сум, поруч видно `Partial`. `$0.00` означає відомий нуль, `—` означає відсутність відомої вартості. |
| **PR Detail → Agent runs → Timeline** · скриншот 1 | Праворуч у рядку запуску, поруч із часом. За наявності токенів — один рядок метаданих під часом, наприклад `9,119 tok · $0.0013` | Вартість конкретного запуску. Під час виконання та за відсутності суми поле вартості пропускаємо, як у рядку з помилкою на референсі. |
| **Agent run → Trace → Stats** · скриншот 2 | `Duration` → `Tokens` → `Cost` → `Findings` | Вартість вибраного запуску, наприклад `$0.06`, або `—`, якщо трасування є, але суми в ньому немає. Під час виконання доступний поточний Live Log, після збереження трасування — картка `Cost` у `Trace`. |

Позначка `Partial`, прочерк і вартість у таймлайні мають зрозумілий доступний текст. На вузькому екрані колонка та картка залишаються доступними, а заголовки й рядки таблиці вирівняні. Порядок карток зберігається, якщо вони переносяться на наступний рядок.

## 3. Правила обліку

- **Запуск агента.** Використовуємо повну суму USD, яку DevDigest отримав від провайдера або оцінив за доступним тарифом під час виконання. Якщо під час виконання не вдалося оцінити хоча б один модельний виклик чи спробу, повна вартість агента невідома. Історичний запис не переоцінюємо за нинішнім тарифом.
- **Остання команда рев’ю.** Для запуску одного агента колонка бере його суму. Для `Run all` складає суми агентів саме цього запуску. Серед команд, чиї агенти вже завершилися, вибираємо найновішу за часом запуску. Поки новіша команда триває, колонка показує вартість попередньої завершеної команди. Новий коміт зберігає останнє значення `Cost` до завершення новішої команди. `Score` відображає результат рев’ю за своїм поточним правилом.
- **Неповна сума.** Два агенти за `$0.06` і `$0.0013` дають `$0.0613`. Якщо відома лише друга ціна, показуємо `$0.0013` і `Partial`. Якщо немає жодної відомої суми, показуємо `—`, навіть коли старіша команда має відому ціну. Відомий нуль бере участь у підсумку.
- **Помилка або скасування.** Якщо до фіксації завершення DevDigest отримав повну суму запуску, показуємо й враховуємо її, навіть коли результат рев’ю не збережено. Якщо рушій перервався до одержання повної суми, вартість агента невідома. Для скасування під час модельного виклику стан ціни визначаємо після того, як виконання зупинилося. Команда, де всі агенти завершилися помилкою або скасуванням, теж може бути останньою завершеною.
- **Видалення.** Видалення запуску доступне після того, як виконання зупинилося й стан ціни записано. Видалення з таймлайну прибирає запуск зі збереженого підсумку команди. Якщо в команди не лишилося запусків, колонка бере попередню завершену команду, якщо вона є. Видалення лише результату рев’ю залишає суму, поки запуск є в історії.
- **Формат.** На всіх трьох екранах однаковий формат USD із 2–4 десятковими знаками. Додатні суми менші за `$0.0001` показуємо як `<$0.0001`. Пояснення до `Cost` вказує, що збережені суми можуть включати оцінки.

## 4. Сценарії та критерії приймання

| ID | Сценарій | За умови → дія → очікуваний результат |
|---|---|---|
| **AC-01** | Перегляд вартості останнього рев’ю | Є дві завершені команди з різними сумами й одна новіша активна → відкрити Pull Requests → `Cost` показує найновішу із завершених команд за часом запуску. Після завершення активної команди видно її ціну. Поява нового коміту сама по собі `Cost` не змінює. |
| **AC-02** | Перегляд таймлайну | Є запуск із відомою сумою → відкрити Agent runs → сума відображається біля часу саме цього запуску. Рядки комітів не мають вартості. |
| **AC-03** | Звірка в сайдбарі | Відкрито трасування General Reviewer або іншого PR-агента → переглянути Stats → `Cost` стоїть між `Tokens` і `Findings` та збігається із сумою запуску в таймлайні. |
| **AC-04** | Нульова й невідома суми | Є запуск із відомим нулем і запуск без суми → відкрити їхні деталі → відомий нуль відображається як `$0.00`. Для невідомої вартості в Stats видно `—`, а в таймлайні поле пропущено. У списку видно `—`, коли в останньої завершеної команди немає відомих сум або ще немає завершеної команди. |
| **AC-05** | Груповий запуск | Остання завершена команда `Run all` містить два запуски за `$0.06` і `$0.0013` → відкрити список → `Cost` дорівнює `$0.0613`. Якщо відома лише друга ціна, видно `$0.0013` з `Partial`. У таймлайні й сайдбарі кожен має власну ціну. |
| **AC-06** | Завершення та помилки | Запуск завершується або зупиняється після скасування → таймлайн, відкритий `Trace` і список підхоплюють збережений результат без перезавантаження. Повна отримана сума лишається доступною навіть після помилки збереження результату рев’ю. Якщо хоча б одна модельна спроба не має ціни чи оцінки, вартість запуску невідома. |
| **AC-07** | Видалення запуску | Є кілька запусків у вибраній команді → видалити один із таймлайну → список оновлює суму й стан `Partial` за рештою. Видалення лише результату рев’ю зберігає його запуск і вартість на всіх екранах. |
| **AC-08** | Межі доступу | Є два PR з однаковими номерами в різних репозиторіях, а один із запусків належить іншому робочому простору → відкрити свій PR або спробувати відкрити чуже трасування → список і таймлайн показують витрати відповідного PR, а користувач не отримує дані чужого запуску. |
| **AC-09** | Дрібні суми й вузький екран | Вартість останнього одиночного рев’ю додатна і менша за одну десятитисячну долара → переглянути три екрани → скрізь видно `<$0.0001`. На вузькому екрані сума й підписи доступні. |

## 5. Межі першої версії та перевірка результату

Фіча охоплює списки PR та локальні запуски агентів у DevDigest Studio. Окремий облік CI, бюджети, сортування за витратами, попередня оцінка ціни запуску й редизайн решти елементів зі скриншотів поза межами цього запиту. Видима сума відображає доступні дані про виконання, тому може відрізнятися від підсумку в рахунку провайдера.

Критерій готовності — PR із двома агентами в одному `Run all` проходить усі три екрани. Список показує групову суму або відому частину з `Partial`. Для кожного агента сума збігається в таймлайні й сайдбарі. Вартість збережених запусків доступна, коли локальний DevDigest працює, навіть якщо GitHub чи провайдер моделі недоступні.

## 6. Правила для крайових випадків

- Для паралельних команд діє порядок запуску. Пізніше завершення старішої команди не змінює вартість у списку, якщо вже є новіша завершена команда.
- Для старих агентських запусків без збереженої ціни показуємо стан невідомої вартості. Історичні групи без явного зв’язку між запусками лишаються без групової ціни.
